# 운항·시험

v2.3.1의 화면 배치·카메라 및 핑크 풍선 운항은 [카메라 버전 안내](vision.md)를 따릅니다. 기존 항로 기록은 항로·Multi-Path 화면의 항로 기록 탭에 있으며, 기존 Jetson NTRIP 정보는 유지됩니다.

[프로젝트 소개](../README.md) · [설치](setup.md) · [로그·분석](data-analysis.md)

## 항로 준비

1. 항로 탭의 **수동 항로 추가**에서 이름과 `waypoint 번호, 위도, 경도`를 입력합니다. 저장 시 UTM 좌표도 보관합니다.
2. 여러 항로 중 최근접 항로를 선택하며 운항하려면 **대루트 추가**에서 이름과 소루트 1개 이상을 직접 선택합니다.
3. **이 대루트로 운항 시작** 또는 **이 소루트로 단일 운항 시작**으로 실행 대상을 정합니다.

초기 항로 저장소는 비어 있습니다. LEFT/CENTER/RIGHT 등의 항로를 자동 생성하지 않으며 이름은 자유입니다. 공통 출발·도착 자동 체크는 편집 보조 기능으로, 필수 조건이나 자동 저장 기능이 아닙니다.

Multi-Path는 유효한 GPS 갱신마다 선택한 그룹의 각 소루트 경로선까지 최소거리를 계산하고 가장 가까운 항로를 선택합니다. 2 m 전환 임계값, 유지시간이나 cooldown은 없습니다. 거리가 수치상 같을 때 현재 항로를 유지합니다.

GPS로 새 항로를 기록할 때는 기존 항로 선택 없이 기록을 시작할 수 있습니다. 최소 2개 지점이 모이기 전에 저장을 시도해도 기록 세션은 취소되지 않습니다. **정지 후 항로 저장**은 Jetson에 저장하며, PC 사본은 **선택 항로 PC 저장**으로 JSON/CSV/GPX를 내보냅니다.

## 출력 확인과 운항

실물 출력 시험은 프로펠러를 제거한 상태에서 조향·스로틀 중립, 출력 방향, RC 수동 전환과 E-STOP을 먼저 확인합니다. 기본 보정은 조향 중심 `6000`, 스로틀 정지 `6450`이며 [boat.yaml](../catkin_ws/src/rcboat_ros/config/boat.yaml)에 있습니다.

일반 자동 운항에서는 GUI/ROS 링크, SSH, GPS·항법·출력 상태를 확인합니다. 기본 제어는 `HEADING`, 순항 PWM `6650`, 속도 피드백 비활성입니다. `target_speed_mps: 0.6`이 실제 주행 속도 0.6 m/s를 보장하지 않습니다.

## Ground Test

GUI의 **도보 테스트** 기능과 로그의 `GROUND_TEST` 명칭은 시험 모드 이름입니다. 파일 이름만으로 실제 시험이 도보였는지 수상 주행이었는지 판단할 수 없습니다. 시험 환경과 수동 개입은 별도 기록으로 함께 남깁니다.

1. 도보 테스트 탭에서 대루트 또는 단일 소루트를 선택합니다.
2. 계산·기록만 확인할 경우 출력 활성화를 체크하지 않고 추진 전원을 분리합니다.
3. 실제 PWM 검증은 프로펠러를 제거한 뒤 **프로펠러 제거 확인 · 자동주행 조향/스로틀 PWM 실제 출력**을 해당 시험에서 명시적으로 선택합니다. 확인 상태는 다음 시험으로 자동 유지되지 않습니다.
4. ROS master/gateway와 GPS 유효 상태를 확인하고 **도보 테스트 시작**을 누릅니다.
5. 기준 경로 위를 이동하며 sample 수와 상태를 확인합니다. 시작 시 기준 항로·설정이 고정본으로 저장됩니다.
6. 시험 중 항로·설정 변경이나 수동 개입이 있으면 이벤트와 별도 변경 로그로 보존합니다.
7. **도보 테스트 종료** 후 완료된 시험을 선택하고 **선택 결과 다운로드**로 ZIP을 받습니다.

계산·기록만 하는 시험의 최종 출력은 중립입니다. 출력 검증을 선택하면 항법 명령이 안전 제어를 거쳐 PCA9685로 전달됩니다. 지상 시험 통과만으로 수상 운항의 제어 가능 범위가 확정되지는 않습니다.

## 수동 전환

E-STOP, 목표 도착, 일반 운항 중 SSH 단절, GUI/ROS 링크 만료, GPS 이상, 항법·RC·출력·추진 오류 발생 시 안전 수동 전환합니다. 구체적인 중립·잠금 동작은 원인과 모드에 따라 적용됩니다.

- 전환 직후 조향 `6000` / 스로틀 `6450`으로 정지합니다.
- RC 스로틀 `1499±31 µs`를 `0.3초` 유지해야 수동 조종이 가능합니다. 기존 중립 구간 전체와 새 실측 지터를 포함합니다.
- GPS·SSH가 없어도 유효한 RC 입력으로 수동 조종할 수 있습니다.
- 수동 전환 후 자동주행은 명시적으로 다시 시작해야 합니다.
- E-STOP은 MANUAL 표시와 별개로 해제 전까지 출력을 잠급니다.

Ground Test는 SSH만 끊겨도 ROS heartbeat가 살아 있으면 계속합니다. 전체 GUI/ROS 링크는 마지막 heartbeat부터 기본 5초 뒤 만료됩니다. 안전 수동 전환 후에도 로거는 기록을 유지합니다. 원인 복구 후 **출력 재개 · 기록 유지**로 이어갈 수 있지만 목표 도착 상태에서는 재개가 거부됩니다. 시험 종료 버튼으로 파일을 마감합니다.

## Ground Test GPS 복구 유예

`ground_test_gps_grace_s: 5.0`은 **GPS 무효·stale 감지 후 추가 유예 시간**입니다. 기존 GPS stale 기준은 2초이므로 수신이 완전히 멈추면 마지막 유효 FIX부터 수동 전환까지 약 7초가 될 수 있습니다. 이 중립 유예는 Ground Test용입니다. NAVIGATION의 별도 전진 유예는 아래 ‘항로 주행 지연과 명확한 단절’을 따르며 AUTO/REMOTE에는 적용하지 않습니다.

| 구간 | 동작 |
|---|---|
| GPS 이상 감지 | GROUND_TEST와 기록을 유지하고 조향·스로틀 중립 잠금 |
| 유예 안에 복구 | 최신 유효 FIX와 그 FIX로 계산한 새 항법 명령을 받으면 자동 재개 |
| 유예 만료 | MANUAL 전환, 자동 출력 해제, 기록 계속 |
| 다른 안전 오류 | 유예 중에도 E-STOP·수동 조작·목표 도착·RC/출력/링크/항법 오류 우선 적용 |

끊기기 전 항법 명령을 재사용하거나 위치를 추정하지 않습니다. FIX가 잠깐 돌아왔다 다시 끊겨도 진행 중인 타이머를 연장하지 않습니다. 설정 범위는 0~30초이며 0이면 유예 없이 전환합니다.

CSV의 `gps_grace_active`, `gps_grace_remaining_s`, `test_pause_reason`과 `GROUND_TEST_GPS_GRACE_STARTED/RECOVERED/EXPIRED/ABORTED` 이벤트로 실제 구간을 확인합니다.

## 추진 이상 판단 범위

기본 구성에는 회전수·전류 센서가 없습니다. 일반 AUTO/NAVIGATION에서 전진 PWM≥6550, GPS 속도<0.15 m/s, 시작점 대비 이동<1 m가 15초 이어지면 `PROPULSION_NO_PROGRESS_SUSPECTED`로 전환합니다. 바람·계류·GPS 오차도 원인일 수 있으며, 스크류 걸림을 확정하는 진단은 아닙니다. Ground Test에는 이 의심 감지를 적용하지 않습니다.

## v2.1.15 RC 입력 보정과 순항 PWM

Arduino 시리얼의 `steering,throttle` 두 정수를 `rc_input_node`가 `/rcboat/rc/input`의 `steering_us/throttle_us`로 발행합니다. 이는 RC 입력 경로이며, PCA 출력 readback 경로가 아닙니다. 제공된 실측값은 사용자가 RC 입력 측정값으로 명시한 값으로 반영했습니다. 현재 main에는 Arduino 펌웨어와 원시 측정 로그가 없어 센서 배선·측정기까지 독립 검증한 것은 아닙니다. PCA는 별도 `ControlCommand`를 받아 16비트 duty를 12비트 카운트로 변환해 60 Hz 설정으로 씁니다. 실제 출력 펄스폭은 이번 작업에서 측정하지 않았습니다.

입력 설정은 `boat.yaml`의 `rc_input_calibration`이며 단위는 µs입니다. 끝점 대표값은 제시된 최소/최대 지터 범위의 중앙값을 반올림한 정수입니다. v2.1.13의 조향 최대 1984.5→1985, 스로틀 최소 1117.5→1118로 맞췄으며 나머지 기준·데드밴드는 유지합니다. 방향을 추정해 숫자를 바꾸지 않았습니다.

| 축 | 입력 최소 / 중립 / 최대 | 중립 데드밴드 | 신호 허용 범위 |
|---|---|---|---|
| 조향 | 1004 / 1620 / 1985 | ±4 (1616~1624) | 970~2011 |
| 스로틀 | 1118 / 1499 / 1881 | ±31 (1468~1530) | 1090~1908 |

신호 허용 범위는 실측 양 끝에 25 µs를 더한 검증 여유이며 새 측정값이 아닙니다. 스로틀 ±31은 중심을 1499로 옮겨도 기존 1470~1530 구간을 모두 유지하기 위한 선택입니다. 설정은 시작 시 검증·고정하므로 변경 후 관련 ROS 노드 재시작이 필요합니다.

데드밴드 안에서는 출력 중립을 정확히 유지합니다. 밖에서는 가까운 데드밴드 경계부터 해당 끝점까지 독립적으로 선형 변환합니다. 예를 들어 하단은 `(입력 - 하단 데드밴드 경계) / (하단 데드밴드 경계 - 최소 입력)`을 사용합니다. 정상 끝점 지터만 포화 처리하며, 누락·비수치·비정상 범위·미래 시각·0.75초 초과 입력은 중립 잠금 및 중립 재확인을 요구합니다.

출력 설정은 조향 `4900/6000/7300`, 스로틀 `5800/6450/7397`입니다. v2.1.15에서 최대 전진을 7000→7397로 변경했으며, 입력 1881µs는 출력 7397에 대응합니다. 수동 입력의 숫자 증가 방향과 자동 항법의 `nav_invert_steering`은 별개입니다. 실물 좌우 방향은 수치만으로 확정하지 않았습니다.

제스처 유지 시간은 기존대로 자동 안전 대기 진입 3초, 수동 전환 0.5초, 스로틀 중립 재허용 0.3초입니다. 제스처는 새 보정값으로 정규화한 조향 상단 85% 이상(약 1930.9 µs)·스로틀 중립, 스로틀 상단 90% 이상(1845.9 µs)을 사용하며 새 실측 끝점에서 도달 가능합니다. 이는 모터 출력 % 표시가 아닙니다.

GUI의 **순항 PWM**은 6480~7390에서 10씩 편집하거나 끝값 **7397**을 지정하고 **적용**을 눌러 전송합니다. 기본값은 6650입니다. 편집값과 backend가 확인한 적용값을 따로 표시하고, 이전 응답이나 상태가 새 편집값을 덮어쓰지 않습니다. 7800 기준 %는 제거했습니다. 실제 GNSS 속도는 별도 m/s 값이며 PWM과 비례한다고 해석하지 않습니다. 큰 회전 시 항법이 순항값에서 출력을 낮추는 기존 동작은 유지합니다. 순항 설정은 실행 중 ROS 설정이며 재시작 기본값은 `boat.yaml`입니다. 적용은 모드·arming·E-STOP을 바꾸거나 장치에 직접 쓰지 않습니다.

### 자동항법 상승 램프

NAVIGATION의 유효한 새 주행 명령에만 상승 램프를 적용합니다. 항법 노드의 기존 방향 오차 감속·초기 대회전 정지를 계산한 뒤, 그 결과를 상한으로 `현재 PWM + (250 / 1.5) × monotonic 경과초`만큼 올립니다. 첫 출력은 `min(6650, 해당 감속 결과)`입니다. 목표 하향·방향 오차 감속은 즉시 반영하고 감속 뒤에는 낮아진 값에서 다시 상승합니다. 안전감독과 actuator는 그 뒤에 적용되므로 E-STOP·확정 오류·항로 완료의 중립 잠금을 램프가 늦추지 않습니다. 기존 GPS 지연 유예 중 6650 출력은 별도 안전 정책이며 변경하지 않았습니다.

| 시작 후 시간(초) | 목표 6900일 때 직진 PWM |
|---|---|
| 0 | 6650 |
| 0.25 | 6692 |
| 0.5 | 6733 |
| 0.75 | 6775 |
| 1.0 | 6817 |
| 1.25 | 6858 |
| 1.5 | 6900 |

고정 상승률은 약 166.7 PWM/s입니다. 최종 지시의 ‘상승률은 기존값 유지’를 적용해 v2.1.14의 `250 / 1.5` PWM/s를 유지하며, 본문 예시의 120 PWM/s로 변경하지 않았습니다. 목표 6750까지 계산상 0.6초, 6900까지 1.5초, 7397까지 약 4.482초입니다. 실제 4 Hz 출력 시점은 그 이후 첫 주기입니다(정상적인 0.25초 간격이면 각각 0.75초·1.5초·4.5초). 통신·스케줄링 지연과 실제 모터 가속 시간은 별도입니다.

최대 전진은 `control_config.py`의 공통 상한 7397과 `boat.yaml`의 `throttle_forward_max: 7397`을 사용합니다. 노드 시작 시 설정 불일치를 거부하므로 이전 YAML의 7000이 조용히 적용되지 않습니다. MANUAL·REMOTE·NAVIGATION·GROUND_TEST 및 actuator·시험 로거가 같은 출력 범위를 확인합니다. 7397 초과 명령은 거부하고 actuator는 중립 처리합니다. 중립 6450, 최대 후진 5800과 조향 범위는 유지하며 ESC 설정·캘리브레이션은 변경하지 않습니다. 이 상한은 사용자가 지정한 명령 범위이며 이번 작업에서 하드웨어 성능을 측정한 결과는 아닙니다.

운항 중 목표 상향은 현재 값에서 이어가고, 소루트 전환은 램프를 초기화하지 않습니다. NAVIGATION 정지·재시작, arming 해제·GPS 유예 등 출력 중단 뒤에는 초기화합니다. 안전감독의 주행 시작 시각과 항법 램프의 시작 시각 식별값이 맞아야 출력하므로, 시작 전/이전 주행의 높은 명령을 먼저 출력하지 않습니다. 다른 모드에는 상승 제한을 적용하지 않습니다.

GUI의 ‘적용 목표’가 backend 확인 목표이며, ‘현재 항법 램프 PWM’은 항법의 제한 결과입니다. 기존 ‘최종 ESC 출력 CH6’은 안전감독 이후 actuator가 전송 성공으로 보고한 명령이고, 툴팁에서 안전감독 명령도 확인합니다. 실제 GPS 속도(m/s)는 기존 속도 카드로 확인합니다. 전송 성공은 실측 회전수나 출력 펄스폭 확인과 다릅니다.

## 항로 주행 지연과 명확한 단절

SSH probe 응답 지연은 첫 실패 확인부터 기본 5초 동안 기존 세션을 유지하며 `delayed`로 표시합니다. 정상 응답이 돌아오면 같은 세션을 유지합니다. transport/인증/터미널 종료가 확인되면 유예 없이 disconnected로 바꾸고 다음 ROS heartbeat에서 MANUAL로 전환합니다. 패킷이 전혀 오지 않는 상태는 순간적으로 지연과 단절을 구별할 수 없으므로 응답 유예 만료로 판단합니다. probe 자체 timeout·주기와 heartbeat 전달 시간이 있으므로 물리 단절 시점과 정확히 같은 순간을 보장하지 않습니다. GUI/ROS lease 5초 만료, RC·출력·항법 오류는 별도로 수동 전환합니다.

NAVIGATION의 GPS **데이터 stale**에는 `navigation_gps_grace_s: 5.0`을 적용합니다. 이 기간은 조향 6000과 `navigation_gps_grace_pwm: 6650`으로 전진합니다. 6650은 실측 최저 항해속도가 아닌 PWM 명령입니다. GPS stale 기준 2초 이후의 추가 유예라서 무수신 시 마지막 FIX부터 총 약 7초가 될 수 있습니다. 유예 중에는 실제 경로 오차를 새로 판단할 수 없으며 기존 조향 명령도 재사용하지 않습니다. GPS가 복구되고 그 FIX로 계산된 최신 항법 명령이 도착하면 같은 항로 진행 상태와 arming을 유지해 재개합니다.

수신기 I/O 오류·명시적인 transport 단절, 최신 FIX invalid, E-STOP·RC·출력·항법·링크 오류와 목표 도착은 유예를 우회해 중립 잠금 및 MANUAL 전환합니다. 유예가 만료돼도 MANUAL로 전환하며 나중에 GPS가 돌아와도 자동 재개하지 않습니다. 따라서 일시 지연은 견딜 수 있지만 오류 상태에서 무조건 완주를 보장하는 동작은 아닙니다. Ground Test의 기존 GPS 유예는 중립 잠금을 유지합니다. `NAVIGATION_GPS_GRACE_STARTED/RECOVERED/EXPIRED/ABORTED` 이벤트와 safety 상태로 구간을 확인합니다.

## HDOP 참고 기준 저장

현재 main의 HDOP는 출력 차단 Gate가 아닌 진단 참고값입니다. GUI도 이 정책을 표시합니다. 편집 중 상태 polling이 값을 되돌리지 않으며, backend ACK와 실제 저장값을 사용합니다. 값은 0.5~20의 유한수만 허용하고 Jetson 로컬 `~/.rcboat/gps_settings.json`에 원자적으로 저장합니다. gateway 재시작 시 로컬 저장값이 `boat.yaml`의 초기 `max_hdop`보다 우선합니다. 시뮬레이션은 메모리에만 저장합니다.
