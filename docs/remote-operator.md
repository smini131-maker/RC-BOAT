# 육상 PC에서 RC 보트 운항

1. 보트에 실을 휴대폰에서 모바일 데이터와 핫스팟을 켭니다. Jetson이 저장된 핫스팟에 연결될 때까지 기다립니다. 휴대폰에서는 핫스팟만 켜 둡니다.
2. 육상 PC를 인터넷이 되는 Wi-Fi나 유선망에 연결합니다. v2.4.19 EXE를 직접 엽니다. 기본 Tailscale 주소와 Windows 자격 증명으로 자동 연결을 시도합니다. 같은 Wi-Fi에서는 연결 설정에서 현재 로컬 IP를 직접 입력할 수도 있습니다. 앱을 다시 열면 Tailscale 주소로 시작합니다.
3. 관제 화면에서 SSH와 ROS gateway가 연결됐는지 확인합니다. 항로 선택, 수동 전환, PC 조이스틱, 비상정지, 카메라와 영상은 기존 관제 화면에서 사용합니다.

## 제어와 영상

Tailscale은 PC와 Jetson 사이 사설 주소를 유지하므로 핫스팟에서 Jetson의 로컬 주소가 바뀌어도 앱 주소를 다시 입력할 필요가 없습니다. 직접 연결이 가능하면 사용하고, 네트워크 조건에 따라 암호화 릴레이를 사용합니다. PC는 별도 인터넷망에 연결할 수 있습니다. [Tailscale 연결 유형](https://tailscale.com/docs/reference/connection-types)

- 운항 명령과 안전 연결 확인은 ROS 게이트웨이 TCP 8765를 사용합니다. SSH TCP 22는 관리 터미널과 SSH 연결 확인용입니다. SSH 접속 재시도와 ROS 상태 조회는 운항 명령과 별도 스레드에서 처리합니다. 항로 목록은 내용이 바뀔 때 전송합니다.
- Windows 관제 앱은 HTTP 8766의 지속 연결로 최신 JPEG를 최대 14fps로 받습니다. 미리보기 데이터는 약 144 KiB/s 이내로 제한하며, 작은 제어 확인 패킷의 최근 응답이 지속해서 늦으면 8fps 또는 5fps로 줄입니다. 풍선 추적 탭에는 Jetson의 판단 fps와 PC 영상 fps가 따로 표시됩니다. 영상은 가운데에 맞춰 전체를 표시합니다. 창이 낮아 영상 영역이 화면을 넘으면 위로 끌거나 휠을 아래로 굴려 영상 영역만 스크롤할 수 있습니다.
- 풍선 감지와 추적 판단은 Jetson에서 실행됩니다. PC에서 풍선 화면을 떠나거나 **실시간 영상**을 끄면 미리보기 요청이 중단됩니다. 이때 Jetson의 추적 연산은 계속 동작합니다.

## v2.4.19 통신 상태

ROS master 상태 확인 불가는 PC가 게이트웨이 응답을 받지 못한 상태입니다. 게이트웨이가 응답하고 master에 접속할 수 없다고 보고하면 offline을 표시합니다. Jetson 터미널에서 서비스 상태를 확인할 수 있습니다.

    systemctl status rcboat_ros tailscaled --no-pager
    journalctl -b -u rcboat_ros --no-pager -n 60

SSH 재접속 간격은 1.5초이고, ROS 제어 확인 응답이 돌아오면 상태 조회를 즉시 다시 시도합니다. 영상은 ROS 상태 조회와 독립적으로 복구하며, 연속 두 번 스트림이 실패하면 약 5초 동안 최신 JPEG로 전환한 뒤 스트림을 다시 시도합니다. VPN에서 이때 최신 JPEG 요청은 최대 초당 5회입니다. 기존 출력 잠금과 제어 연결 안전 규칙은 그대로 적용됩니다.

## Jetson을 다시 켰을 때

Jetson의 현재 휴대폰 핫스팟 프로필은 자동 연결로 저장돼 있습니다. Tailscale과 ROS 서비스도 부팅 시 자동 시작으로 설정돼 있습니다. 휴대폰 데이터와 핫스팟이 켜져 있고 VPN 장치 로그인이 유효하면, Jetson의 로컬 IP가 달라져도 PC가 저장한 Tailscale 주소로 다시 연결합니다.

## 연결이 끊기는 경우

- 육상 PC와 보트 사이에 별도 인터넷망을 쓰면 양쪽 인터넷이 모두 필요합니다. 현장 망에서 직결이 불가능해 릴레이를 사용하거나 LTE/5G 업로드가 느리면 미리보기 프레임 수가 줄고 조작 응답도 느려질 수 있습니다.
- PC의 실제 SSH 단절이 확인되거나 제어 연결 확인이 만료되면 항로 주행과 풍선 추적은 기존 안전 규칙에 따라 수동으로 전환됩니다. 다시 연결되면 운항 상태를 확인하고 PC에서 직접 시작합니다. 인터넷 단절 중에는 RC 조종기로 수동 회수합니다.
- 새 PC에서는 Tailscale을 같은 사설망에 등록하고, 해당 PC에서 SSH 호스트 키와 비밀번호를 저장합니다. 배포 파일에는 자격 증명이 들어 있지 않습니다.

## v2.4.12 비교 측정

PC와 Jetson을 같은 휴대폰 핫스팟에 둔 상태에서 LAN 주소와 Tailscale 직결 주소를 비교했습니다. 각 조건에서 ROS 상태 요청을 16번 보냈습니다. 아래 영상 수치는 Windows 미리보기와 같은 요청 간격 계산을 사용한 HTTP 측정값입니다.

| 경로 | 영상 수신 | ROS 상태 왕복 중앙값 / p95 | 미리보기 | 영상 요청 중앙값 / p95 |
|---|---|---|---|---|
| LAN | 끔 | 351 / 579 ms | — | — |
| LAN | 켬 | 140 / 307 ms | 11.5 fps · 122.1 KiB/s | 13 / 79 ms |
| Tailscale 직결 | 끔 | 133 / 269 ms | — | — |
| Tailscale 직결 | 켬 | 135 / 253 ms | 10.8 fps · 113.7 KiB/s | 18 / 60 ms |

Jetson의 판단은 약 14.9 fps였고 영상 수신 중에도 유지됐습니다. 위 수치는 이 시험의 결과입니다. 별도 육상 Wi-Fi와 LTE/5G 핫스팟을 연결하거나 릴레이를 쓰는 환경의 성능은 현장 망에 따라 달라집니다.

## v2.4.13 별도 Wi-Fi 재시험

Jetson을 휴대폰 핫스팟에 둔 채 PC의 별도 Wi-Fi를 5초씩 끊고 두 번 복구했습니다. Windows가 인터넷 복구를 보고한 시각부터 ROS는 약 0.1~1.3초, SSH는 1.5~2.9초 걸렸습니다. 영상 탭을 연 시험에서는 같은 기준으로 약 0.3초 뒤 영상도 다시 들어왔습니다. 재연결 요청부터 ROS 복구까지는 약 6.6~7.1초였고, 회선 복구 이후에도 별도의 간헐적 끊김이 관측됐습니다.

- 화면에서 PC 영상 11.6fps, Jetson 판단 15.0fps를 확인했습니다. 같은 영상의 JPEG 표본 10장으로 추정한 촬영부터 수신까지의 지연은 중앙값 약 228ms, 표본 최대 409ms였습니다.
- 영상이 켜진 상태에서 수동과 자동 대기 전환 명령 3회의 응답은 약 190~356ms였습니다. ROS 조회 반영은 0.54~0.75초였으며 출력은 잠근 상태였습니다.
- 항로 목록을 이미 받은 상태에서 ROS 응답은 약 113KB에서 약 13.4KB로 줄었습니다. 15초 시험에서 미리보기 끔과 켬 모두 Jetson 판단 중앙값은 14.9fps였습니다. CPU 코어 평균 사용률의 중앙값은 약 38%에서 43%로 늘었습니다.
- Jetson의 현재 Wi-Fi 자동 연결과 Tailscale·ROS 부팅 설정을 확인했습니다. 이번 재연결 시험에서는 Jetson 전원을 유지했습니다.

## v2.4.14 현장 확인

- EXE를 옵션 없이 직접 실행했고 저장된 Tailscale 주소로 SSH와 ROS가 연결됐습니다.
- Windows 앱의 풍선 추적 탭에서 위로 끌어 영상 아래쪽이 나타나는 것을 확인했습니다. 새 프레임이 표시되어도 스크롤 위치가 유지됩니다.
- 별도 Wi-Fi에서 12fps 설정의 수신은 11.8fps, 14fps 설정은 11.3fps였습니다. Jetson 판단은 두 경우 약 14.9fps였으며 CPU 중앙값은 약 42%였습니다. 14fps의 수신 개선이 확인되지 않아 시험 장치의 저장된 미리보기 설정은 12fps로 복구했습니다.
- PC가 별도 Wi-Fi에서 휴대폰 핫스팟으로 넘어간 뒤 앱을 건드리지 않아도 ROS와 SSH가 복구됐습니다. 네트워크가 달라진 시험이므로 이전의 같은 Wi-Fi 재연결 측정과 직접 비교하기 어렵습니다.


## v2.4.19 현장 준비

Android도 첫 연결에서 항로 목록을 받고, 목록이 바뀔 때만 다시 받습니다. 현재 모드, 목표점, 위치 같은 실시간 상태는 매번 갱신합니다. 기존 항로 7개로 측정한 Tailscale 상태 응답은 중앙값 약 110 kB에서 10.4 kB로 줄었습니다. 이 측정은 PC와 Jetson이 같은 Wi-Fi에 있는 동안 수행했습니다.

야외에서는 보트에 실을 휴대폰을 핫스팟으로 두고 PC를 육상 네트워크에 연결한 상태에서 시험합니다. 출력 잠금 상태에서 SSH, ROS, 영상과 RC 수동 전환을 확인한 뒤 운항합니다. Tailscale 연결 유형을 확인하려면 PC PowerShell에서 다음 명령을 실행합니다.

~~~powershell
tailscale ping --c=5 --until-direct=false 100.74.153.81
~~~

직접 연결과 릴레이에서 지연이 달라질 수 있습니다. 현장 시험 중 PC 인터넷을 잠시 끊었을 때 수동 전환과 재연결을 확인하고, 재연결 뒤에는 모드를 직접 선택합니다.
